# 摄像头方案说明与调整约束

## 1. 结论

当前 `test.py` 使用的 YuNet + SFace 方案不能作为课程需求的正式实现。

原因不是参数还没有调好，而是方案本身与需求不一致：

1. YuNet 检测的是“可见人脸”，不是“人头/人员”。
2. SFace 提取的是人脸身份特征，违反“不做人脸识别、不识别身份”的隐私要求。
3. 当前脚本没有向后端上报数据。
4. 当前脚本固定座位数，不能与后端教室数据同步。

允许把 YuNet 临时用于前端/后端接口联调演示，但不能作为最终验收方案。正式方案应改为在教室本地运行的 YOLO 人员/人头检测客户端。

---

## 2. 需求原文约束

需求要求：

- 摄像头按固定间隔抽帧。
- 使用 YOLO 预训练模型检测人头。
- 统计当前在场人数。
- 按座位总数计算实时占用率。
- 向后端上报教室编号、人数、占用率、采集时间。
- 前端展示实时占用率。
- 摄像头故障或离线不影响预约核心功能。
- 只做人头计数。
- 不做人脸识别，不识别身份。
- 不存储原始画面。
- 在本地推理。
- 服务器只接收占用率数字。

因此最终方案必须同时满足“模型目标正确”和“隐私边界正确”。

---

## 3. 当前方案的问题

### 3.1 YuNet 检测对象错误

YuNet 输出人脸框。它通常只能稳定检测：

- 正面或较清晰的人脸。
- 没有严重遮挡的人脸。

教室常见场景会造成漏计：

- 学生背对摄像头。
- 低头看书或看手机。
- 侧脸。
- 前排遮挡后排。
- 逆光或远距离小脸。

因此 YuNet 统计的是“可见脸数量”，不等于“在场人数”。

### 3.2 SFace 违反隐私要求

SFace 会提取人脸 embedding，并与历史特征比对。

即使没有把特征上传服务器，也仍然属于：

- 人脸识别。
- 生物特征处理。
- 身份去重。

这与需求明确要求的“不识别身份”冲突，正式版本必须删除。

### 3.3 关闭身份识别后的计数逻辑仍有缺陷

原脚本将：

```python
ENABLE_IDENTITY = False
```

作为“纯人头计数”降级模式，但该模式下使用全零特征。零特征无法达到：

```text
MATCH_SIM_ACTIVE
MATCH_SIM_HISTORY
IOU_FALLBACK_SIM
```

其中 IoU 兜底还被 `best_s >= IOU_FALLBACK_SIM` 门槛阻止，结果可能为每个检测框不断创建新轨迹，导致人数按帧数被重复累计。

正式实现必须使用不依赖人脸特征的运动跟踪，例如 IoU、中心点距离或 ByteTrack 类跟踪。

### 3.4 座位数硬编码

原脚本：

```python
SEAT_TOTAL = 40
```

不同教室座位数不同，而且后端已经有 `seatCount`。摄像头端必须从：

```http
GET /api/v1/ai/config
```

获取实际座位数。

### 3.5 没有接入后端

原脚本只：

- 打开摄像头。
- 本地显示人数。
- 写 CSV。

没有调用：

```http
POST /api/v1/ai/occupancy/report
```

因此后端和前端仍无法获得摄像头数据。

### 3.6 没有设备鉴权

任何知道地址的人都能伪造人数。正式摄像头客户端必须使用独立设备 Token。

## 4. 目标架构

```text
教室摄像头
  |
  v
本地 YOLO 人员/人头检测
  |
  v
本地轨迹跟踪与去重
  |
  v
计算当前人数和占用率
  |
  v（只发送数字）
HTTPS /api/v1/ai/occupancy/report
  |
  v
Spring Boot
  |
  v
MySQL + 前端展示
```

原始视频和图片始终保留在本地内存中，不发送到云服务器。

---

## 5. 推荐模型与算法

### 5.1 模型

优先选择能够在教室本地稳定运行的 YOLO 人员/人头模型，例如：

- YOLO 预训练人员检测模型。
- 经过课堂视角微调的人头检测模型。
- ONNX 格式的轻量 YOLO 模型，便于边缘设备部署。

如果只能使用通用 COCO 人员检测模型，应记录“检测到的人员框”，不要退回到人脸检测。

### 5.2 跟踪

模型只负责检测框，人数需要跟踪后统计：

1. 检测所有人员/人头框。
2. 使用 IoU 或中心点距离关联上一帧轨迹。
3. 连续命中达到阈值后才确认进入。
4. 超过超时时间未出现才确认离开。
5. 当前人数等于活跃轨迹数量。
6. 同一帧一个轨迹只能匹配一个检测框。

不得使用人脸 embedding 去重。

### 5.3 建议参数

以下参数应通过配置提供，不写死在业务逻辑中：

```text
inferenceIntervalSeconds
confidenceThreshold
iouThreshold
trackTimeoutSeconds
minHitsToConfirm
cameraSource
```

具体默认值应根据实际摄像头和场景标定，不能把未经测试的数值当成验收结果。

## 6. 后端已提供的接口

完整定义见[接口契约](./api-v1.md)。

### 6.1 获取配置

```http
GET /api/v1/ai/config
X-Device-Id: <设备ID>
X-Device-Token: <设备Token>
```

返回：

```json
{
  "classroomId": 4,
  "roomNo": "A101",
  "seatCount": 96,
  "reportIntervalSeconds": 30,
  "staleAfterSeconds": 300,
  "serverTime": "2026-11-15T10:00:00+08:00"
}
```

### 6.2 上报占用率

```http
POST /api/v1/ai/occupancy/report
X-Device-Id: <设备ID>
X-Device-Token: <设备Token>
Content-Type: application/json
```

请求：

```json
{
  "classroomId": 4,
  "deviceId": "cam-A101-01",
  "headCount": 42,
  "occupancyRate": 43.75,
  "collectedAt": "2026-11-15T10:00:00+08:00",
  "source": "REAL",
  "sequence": 1001
}
```

成功：

```json
{
  "recordId": 101,
  "currentUpdated": true,
  "serverTime": "2026-11-15T10:00:01+08:00"
}
```

## 7. 必须遵守的变量和字段

### 7.1 请求头

| 字段 | 类型 | 约束 |
|---|---|---|
| `X-Device-Id` | string | 必填，与请求体 `deviceId` 一致 |
| `X-Device-Token` | string | 必填，不得写入日志或源码 |

### 7.2 上报字段

| 字段 | 类型 | 约束 |
|---|---|---|
| `classroomId` | integer | 必填，必须与设备绑定教室一致 |
| `deviceId` | string | 必填，必须与 `X-Device-Id` 一致 |
| `headCount` | integer | 必填，不能小于 0 |
| `occupancyRate` | decimal | 必填，后端保留两位小数并重新校验 |
| `collectedAt` | string | 必填，ISO 8601 带时区 |
| `source` | string | `REAL` 或 `SIMULATED` |
| `sequence` | integer | 必填，设备内单调递增，不能重复 |

### 7.3 计算规则

```text
occupancyRate = headCount / seatCount * 100
```

结果保留两位小数。

后端会重新计算。客户端值与后端计算值误差超过 `0.05` 时返回：

```text
422 OCCUPANCY_RATE_MISMATCH
```

### 7.4 时间规则

- 使用 `Asia/Shanghai` 时间的带时区字符串。
- 示例：`2026-11-15T10:00:00+08:00`。
- `collectedAt` 必须是摄像头完成本次推理的时间。
- 不能使用服务器接收时间代替。

### 7.5 序号规则

- 每次新推理结果使用新序号。
- 网络重试同一结果时复用原序号。
- 后端通过 `(deviceId, sequence)` 去重。
- 采集时间早于当前教室最后时间时，不覆盖当前人数。

---

## 8. 隐私与数据边界

必须做到：

- 摄像头原始画面只在本机内存处理。
- 不上传视频、图片、截图或人脸特征。
- 不保存人脸 embedding。
- 不做身份匹配。
- 不记录姓名、学号或人员身份。
- CSV 日志最多记录时间、人数和占用率数字。
- 摄像头端日志不得包含设备 Token。

禁止恢复：

```text
SFace
人脸 embedding
历史人脸特征库
身份相似度
人脸身份去重
```

---

## 9. 异常处理

### 9.1 摄像头打不开

- 不发送 `headCount=0`。
- 记录本地错误。
- 等待重试，不上传虚假真实数据。

### 9.2 网络失败

- 只缓存待发送的数字结果。
- 使用有限次数指数退避。
- 重试复用原 `sequence`。
- 缓存必须设置上限，不能无限增长。

### 9.3 上报乱序

- 后端写入历史记录。
- 如果采集时间早于当前值，不覆盖教室当前占用率。
- 响应 `currentUpdated=false`。

### 9.4 摄像头离线

- 预约系统继续正常工作。
- 前端超过 `staleAfterSeconds` 后显示“暂无实时数据”。
- 不把旧占用率继续当作当前数据。

---

## 10. 降级与模拟数据

开发阶段可以使用：

```text
source=SIMULATED
```

但必须：

- 使用开发环境设备凭据。
- 页面明确标识为模拟数据。
- 不能把模拟数据写入正式验收结果。

正式环境默认不启用模拟上报。

---

## 11. 建议的客户端流程

```text
启动
  -> 从环境变量读取设备ID和Token
  -> GET /api/v1/ai/config
  -> 应用 classroomId、seatCount、reportIntervalSeconds
  -> 打开摄像头
  -> 按间隔抽帧
  -> YOLO 人员/人头检测
  -> 轨迹跟踪
  -> 生成当前人数
  -> 计算占用率
  -> POST /api/v1/ai/occupancy/report
  -> 成功则递增 sequence
  -> 失败则按原 sequence 重试
```

## 12. 验收标准

### 12.1 功能

- 能读取本地或网络摄像头。
- 能使用 YOLO 检测人员/人头。
- 能按固定间隔推理。
- 能从后端读取真实座位数。
- 能持续上报并更新前端。
- 摄像头断开后预约核心功能无影响。

### 12.2 隐私

- 全流程不调用 SFace。
- 不产生人脸 embedding。
- 不写入原始图片或视频。
- 网络抓包中只有数字 JSON。

### 12.3 计数

至少测试：

- 单人进入和离开。
- 多人同时进入。
- 背对摄像头。
- 侧脸和低头。
- 前后排遮挡。
- 短时间离开后返回。
- 门口路过但未进入。

测试结果应记录误计和漏计，不应只用一张理想图片证明模型可用。

### 12.4 接口

- 设备 Token 错误时返回 401。
- 人数为负时返回 400/422。
- 占用率不一致时返回 422。
- 重复序号不重复写记录。
- 乱序上报不覆盖最新值。
- 前端在数据超时后显示无实时数据。
